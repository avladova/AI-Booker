# AI-Бухгалтер: первичка и денежный план

Это рабочий **клиентский MVP** для двух задач бухгалтерского контура: распознавания русскоязычных первичных документов и контроля прогнозных кассовых разрывов. Приложение запускается как статический сайт, поэтому файлы пользователя обрабатываются прямо в браузере и не передаются этим приложением на сторонний OCR API.

## Реализованные возможности

| Модуль | Что делает пользователь | Что делает приложение |
|---|---|---|
| Распознавание первички | Загружает JPG, PNG, WEBP или PDF до 15 МБ | Для изображений запускает локальный браузерный OCR; для PDF извлекает текстовый слой или распознаёт до пяти первых отрендеренных страниц. |
| Реестр и верификация | Проверяет и редактирует поля в карточке | Выделяет тип документа, номер, дату, ИНН, контрагента, сумму и НДС; показывает OCR-текст и оценку качества. |
| Кассовый план | Вводит ожидаемые операции вручную или загружает CSV | Рассчитывает 30-дневный дневной остаток с учётом вероятности исполнения платежа. |
| Риск дефицита | Указывает начальный остаток и резерв | Показывает первую дату дефицита, минимальный остаток, размер потребности для восстановления резерва и операции для проверки. |
| Экспорт | Нажимает «Скачать реестр JSON» | Сохраняет документы, операции и допущения расчёта в локальный JSON-файл. |

## Быстрый старт

Откройте опубликованную версию на [GitHub Pages](https://avladova.github.io/AI-Booker/) или скачайте репозиторий и откройте `index.html` через локальный статический сервер. Для кассового плана задайте начальный остаток и минимальный резерв, затем добавьте ожидаемые поступления и списания. CSV-шаблон доступен по кнопке в интерфейсе; обязательны поля `дата`, `направление` и `сумма`.

> Перед использованием реквизитов в учёте бухгалтер должен подтвердить их по оригиналу документа. Оценка OCR отражает качество прочтения текста, а не юридическую корректность первички.

## Метод расчёта кассового разрыва

Для каждого дня горизонта приложение использует только введённые пользователем операции. Вероятностная сумма операции равна `сумма × вероятность исполнения / 100`.

> `Остаток дня = Остаток вчера + Σ(поступления × вероятность) − Σ(списания × вероятность)`.

Кассовый разрыв фиксируется, когда остаток становится ниже заданного минимального резерва. Суммы трактуются как полные движения денежных средств, включая НДС, если он входит в оплату. Это прозрачный финансовый план, а не статистическая модель, которая придумывает будущие платежи без подтверждённой истории.

## OCR и обработка PDF

Для изображений используется открытая библиотека [Tesseract.js](https://github.com/naptha/tesseract.js) с русской и английской языковыми моделями `rus+eng`. Проект Tesseract.js запускает WebAssembly-версию OCR в браузере и допускает подключение обычным CDN-скриптом [1]. Русская языковая модель `rus` входит в официальный набор моделей Tesseract; для промышленного внедрения следует выбрать между наборами `fast` и `best` на собственной контрольной выборке первички [2].

PDF с текстовым слоем обрабатываются без OCR. Для сканов используется [PDF.js](https://github.com/mozilla/pdf.js): страница рендерится в изображение, после чего обрабатывается тем же локальным OCR. В текущем MVP лимит — первые пять страниц PDF, чтобы не блокировать браузер на больших пакетах.

## Ограничения MVP и следующий этап

Статическая версия не имеет авторизации, серверного хранилища, интеграций 1С/банков, журнала аудита и модели временных рядов, обученной на банковской выписке. После накопления фактических дат поступления и оплаты следующий этап должен включать серверный контур, ролевую модель, хранение согласованных данных, сверку с банком и бэктестирование вероятностей контрагентов.

При выборе специализированного русскоязычного движка необходимо отдельно проверять лицензию на код и веса. Например, Occular-OCR позиционируется для русских документов, но бесплатность его весов ограничена отдельной категорией малых организаций, поэтому он не может без дополнительной проверки быть универсальной бесплатной заменой для всей целевой аудитории [3].

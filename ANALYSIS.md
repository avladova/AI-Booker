# Первичный аудит AI-Бухгалтер

**Дата анализа:** 18 августа 2026 г.

## Источники требований

Материалы заявки описывают облачный сервис для МСБ России с приёмом первичных документов, извлечением реквизитов, сопоставлением оплат, проводками и интеграциями. В рамках этой итерации приоритет отдан двум запрошенным пользовательским возможностям: распознаванию первичных документов и прогнозу кассовых разрывов.

В бизнес-плане указаны следующие ориентиры для MVP: единое представление документов из файлов, ЭДО, почты и банков; извлечение суммы, ИНН и даты; контроль качества через ручную верификацию; анализ временных рядов для прогноза кассовых разрывов. Целевые метрики заявки — F1 выше 0,95 для ключевых реквизитов и прозрачный контроль результатов пользователем.

## Состояние репозитория

Репозиторий `avladova/AI-Booker` содержит один статический файл `index.html` и краткое описание. Опубликованный GitHub Pages-прототип соответствует этому файлу: это интерфейс-демонстрация без обработчика загрузки, серверного API, хранилища данных, реального OCR, расчёта прогноза или тестов.

## Ограничения и решение для MVP

Так как текущий репозиторий является статическим GitHub Pages-сайтом, реализовать надёжный OCR полностью в браузере можно только через локальную WASM-библиотеку, что потребует значительной загрузки и даст нестабильное качество по разнотипной первичке. Для функционального MVP будет создан интерфейс, который работает с реальными файлами в браузере, выполняет OCR локально при наличии движка, извлекает реквизиты правилами, показывает уверенность и предоставляет ручное подтверждение. Прогноз кассового разрыва будет рассчитываться на основе загруженной пользователем таблицы операций либо демонстрационных данных и явно показывать допущения.

Следующий этап — выбрать открытый OCR-движок с русским языком, определить минимальную схему входных данных и интегрировать полнофункциональный интерактивный интерфейс без передачи бухгалтерских документов внешним сервисам.

## Проверка интерфейса

Локальная версия приложения успешно загружается в браузере: доступны загрузка файлов, поля реестра, расчётные параметры, форма ожидаемой операции и импорт CSV. При изменении начального остатка и резерва пересчитываются ключевые показатели и график даже до добавления операций. Следующая проверка — добавление поступления и списания, чтобы подтвердить расчёт вероятностного потока и идентификацию дефицита.

Добавление тестового поступления 90 000 ₽ с вероятностью 80% корректно создало строку в плане и учло в прогнозе 72 000 ₽. При начальном остатке 100 000 ₽ и резерве 50 000 ₽ итоговый остаток на горизонте стал 172 000 ₽, а система корректно показала отсутствие нарушения резерва. Выбран режим списания для следующей операции.

Тест дефицита пройден. При добавлении списания 180 000 ₽ на 20 августа прогнозный остаток стал −8 000 ₽, первый дефицит определён на 20 августа, а потребность для восстановления резерва 50 000 ₽ — 58 000 ₽. Интерфейс вывел операцию-источник риска и нейтральные действия для проверки договорных сроков и выписки. Формула рассчитана корректно: 100 000 + (90 000 × 80%) − 180 000 = −8 000 ₽.

Реальный локальный OCR-тест успешно завершён на тестовом изображении русскоязычного счёта. Браузерный OCR выделил тип «Счёт», номер INV-245, дату 19.08.2026, ИНН 7701234567, сумму 125 000 ₽, НДС 20 833,33 ₽ и контрагента «ООО Альфа». Отображаемая оценка качества составила 97%. Исходный распознанный текст доступен в карточке для аудита.

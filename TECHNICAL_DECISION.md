# Техническое решение для MVP

## Выбранная реализация

В репозитории уже опубликован статический сайт на GitHub Pages, поэтому MVP реализуется как **клиентское веб-приложение без серверной передачи документов**. Это даёт немедленно развёртываемый результат и исключает отправку первички стороннему OCR API.

Для распознавания используется `Tesseract.js` с открытой русской языковой моделью `rus` и английской `eng`. Библиотека запускает WebAssembly-версию Tesseract в браузерном worker и допускает подключение через обычный CDN-скрипт; официальная документация Tesseract содержит языковую модель `rus` и варианты `fast`/`best` для компромисса между скоростью и качеством. [1] [2]

| Компонент | Решение MVP | Причина |
|---|---|---|
| OCR изображений | Tesseract.js + `rus+eng` | Открытый код, обработка в браузере, русские и латинские реквизиты, подходит для статического хостинга. |
| PDF | PDF.js: извлечение текстового слоя либо рендер первой страницы в изображение | Позволяет обработать обычные и сканированные PDF без backend. |
| Извлечение реквизитов | Нормализованный OCR-текст + прозрачные регулярные выражения | Результат можно редактировать и подтверждать бухгалтеру. |
| Контроль качества | Уверенность OCR, статусы проверки, поля для ручной корректировки | Низкая уверенность не должна создавать учётную операцию автоматически. |
| Прогноз кассы | Детерминированный дневной план: остаток + ожидаемые притоки − ожидаемые оттоки | Проверяемая формула и немедленный расчёт при изменении операций. |

## Логика прогноза

Пользователь загружает CSV операций или вводит их вручную: дата, направление (`Доход`/`Расход`), сумма, контрагент, вероятность исполнения и комментарий. Для каждого дня горизонта считается:

> `конечный остаток = начальный остаток + Σ(ожидаемые поступления × вероятность) − Σ(ожидаемые списания × вероятность)`.

Кассовый разрыв фиксируется, когда прогнозный остаток становится меньше заданного минимального резерва. Интерфейс показывает дату первого дефицита, максимальный дефицит, длительность и операции, связанные с риском. При отсутствии операций на отдельный день баланс переносится без искусственно сгенерированных платежей. Это не статистический прогноз «из воздуха»: вероятностное прогнозирование по истории возможно только после загрузки достаточной фактической временной серии.

## Ограничение «российского OCR» и дальнейший шаг

Свободный русский-first проект Occular-OCR способен работать с изображениями и PDF локально, однако условия его весов бесплатны лишь для очень малых организаций: до 20 млн ₽ годовой выручки и менее восьми сотрудников. [3] Поэтому использовать его как единственный «бесплатный» движок для всей целевой аудитории МСБ из заявки нельзя. Для production-версии следует сравнить Tesseract с self-hosted OCR на размеченной выборке первички; при выборе Occular-OCR необходимо автоматически контролировать лицензионную пригодность клиента.
